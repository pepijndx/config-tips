Inleiding

In dit document worden de verschillende user stories besproken waarbij ook de acceptance criteria en de prioriteit zijn vermeld per onderdeel. Verder in het document staat de Definition of Done opgenomen die wij hanteren om het beste resultaat te behalen.

Epic

E1: De applicatie is gespecialiseerd in Apk-keuringen en kleine reparaties. Het systeem is een webapplicatie en omvat een registratiesysteem, een afspraakbeheersysteem, een planningsysteem, notitie-functionaliteit, e-mailservice en facturatie.

User Stories

Manager (Hoofdbeheerder)

F1: Authenticatie & Autorisatie

US1: Als manager moet ik kunnen inloggen met mijn inloggegevens zodat ik toegang krijg tot de applicatie met verhoogde rechten.

Acceptance Criteria:

  • [AC1]: De e-mail en wachtwoord zijn verplichte velden
  • [AC2]: De manager moet worden doorgestuurd naar de homepagina na het inloggen

Prioriteit: 1 (Must) Het is essentieel dat de manager kan inloggen zodat hij/zij toegang heeft tot het systeem.

Definition of Done

  • Code is geschreven en voldoet aan de code standaarden.
  • De code is gereviewed door minstens één ander teamlid.
  • De applicatie is duidelijk gedocumenteerd.
  • Alle functionaliteiten hebben een unit test en slagen.
  • Er wordt voldaan aan de acceptance criteria.
  • De code is efficiënt en bevat geen prestatieproblemen.
